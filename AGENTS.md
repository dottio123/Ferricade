# AGENTS.md

Contributor guidance for everyone working in Ferricade, including coding agents.
This file describes the project conventions and contribution rules.

## What this is

ferricade: a self-hosted admin console that is the API server for stock
RustDesk clients (1.5.0 tested), next to unmodified `hbbs`/`hbbr`. Devices
report in, wait in an approval queue, show online status, and admins get
`rustdesk://` connect links. Everything an admin does goes to an append-only
audit log. Open source, not affiliated with RustDesk.

## Commands

Go 1.27 (go.mod says `go 1.26`). Postgres 16 for anything that touches the
database.

```sh
go build ./...
go vet ./...
gofmt -l .                       # must print nothing
make sqlc                        # after changing internal/store/queries or migrations
go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 diff   # must print nothing; CI runs it

# Tests that need Postgres skip unless TEST_DATABASE_URL is set;
# REQUIRE_DB=1 makes them fail instead (CI sets it).
docker run -d --name ferricade-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
TEST_DATABASE_URL='postgres://postgres:postgres@localhost:5432/postgres?sslmode=disable' REQUIRE_DB=1 go test -race ./...
```

On Windows, App Control (WDAC) may block the test binaries `go test` builds.
Then run the Go commands in a `golang` container with the repo mounted, e.g.
`docker run --rm -v "$PWD:/src" -w /src golang:1.27 go test ./...` (add a
network and `TEST_DATABASE_URL` for the database tests).

Web UI: Node 24, run in `web/`. CI runs all the checks below.

```sh
npm install              # in the shared checkout; npm ci (CI only) empties node_modules under a running dev server
npm run gen:api          # src/api/schema.d.ts from openapi.yaml; gen:api:check fails if stale
npm run typecheck
npm run lint
npm test                 # Vitest
npm run build            # web/dist (embedded by go:embed), then check-dist (CSP, no mocks)
npm run build:mock       # dist-mock/, with the mock API; never embedded
npm run e2e              # builds both, then Playwright (Chromium)
npm run e2e:live         # Docker: real ferricade + Postgres (project ferricade-e2e, port 21220), rdsim, e2e-live/
npm run dev              # dev server with the mock API
npm run dev:live         # dev server proxied to a real ferricade (FERRICADE_URL = its PUBLIC_URL)
```

Run the stack: `README.md` (Quick start; on Windows, its PowerShell section).

## Live updates

`GET /admin/api/v1/events` is a server-sent event stream. Each message is
`event: <type>` plus `data: <json>`, where the JSON is the `LiveEvent` schema
of `openapi.yaml` (type and IDs only; the client refetches). Types:
`device.updated`, `device.enrolled`, `device.deleted`, `device.online`,
`device.offline`, `session.started`, `session.updated`, `session.ended`, `audit.created`,
`preferences.updated`, `group_rules.updated`, and `resync`, after which the server
ends the stream
and the client reconnects and refetches everything. A User's stream carries only
events about their visible devices and their own audit entries, and ends with resync
when their grants, role or visible devices change. Database changes reach
the hub through triggers that `NOTIFY ferricade_events` (migrations `00002`,
`00004`, `00005`, `00006`); an event derived from audit actions may instead be
mapped in `internal/events/listen.go` from the audit notification (as
`group_rules.updated` is). Add new event types to the appropriate mapping,
`LiveEvent` and the events tests together.

## Rules for everyone

1. **The API contract is `internal/adminapi/openapi.yaml`.** Never assume an
   endpoint, field, status code or error code that is not in it. If you need
   one that does not exist, open an issue or explain the gap in your pull request;
   do not invent it or mock around it silently.
2. **Do not edit generated code** (`internal/store/db`). Change the SQL and
   run `make sqlc`.
3. **Never edit an applied migration.** Add a new numbered one.
4. **Tests first.** Write the test, watch it fail for the right reason, then
   make it pass. A test that passed before your change proves nothing.
5. **Show evidence.** Do not report something as done, fixed or passing
   without the command you ran and its output.
6. **Security is not optional here.** The admin listener is internet-facing.
   Keep: CSRF header + `Origin` check on every state-changing request,
   `__Host-` session cookie (HttpOnly, Secure, SameSite=Strict), no secrets
   in logs or responses, every admin change audited in the same transaction.
   Never weaken these to make something work.
7. **No secrets in the repo.** `deploy/.env` is git-ignored; keep it that way.
8. **Commits** should use a clear message. Add a `Co-Authored-By` trailer when
   an agent wrote the code. Work on a branch; do not commit to `main`.
9. **Stay in scope.** Do the task you were given. Note other problems you see
   instead of fixing them on the side.
10. **When stuck, stop.** After two failed attempts at the same thing, document
    what you tried and what happened, then open an issue or explain the blocker
    in your pull request. Do not keep trying variations.

## Conventions

- Go: standard library first, `chi` for routing, `pgx` + `sqlc` for data,
  `testify` in tests. Errors wrapped with context (`fmt.Errorf("x: %w", err)`).
  Comments say why, not what.
- Admin API errors: `{"error":{"code":"…","message":"…"}}`. Client API errors
  (RustDesk's format): `{"error":"…"}`.
- Times are UTC `timestamptz`; IDs are UUIDs, except the device's
  `rustdesk_id` and `uuid`, which are client text.
- Line endings: LF for Go, SQL and YAML (`.gitattributes`). On Windows the checkout uses
  `core.autocrlf=true`; if `gofmt -l .` lists every file, refresh the checkout's line endings
  rather than reformatting.
