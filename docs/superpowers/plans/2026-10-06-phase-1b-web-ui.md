# Phase 1b Web UI Implementation Plan

> **For agentic workers:** Part A is for Claude (REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans). Part B is a set of briefs for Gemini in Antigravity: one brief per task, done in order, each reviewed by Claude before the next starts. Gemini reads `GEMINI.md` and `AGENTS.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the rdadmin web console (spec: command center, devices, sessions, audit, groups and tags, users, settings, setup wizard, sign-in) on top of the Phase 1b backend.

**Architecture:**
- `web/` is a React + TypeScript + Vite single-page app, built into `web/dist` and embedded in the Go binary (backend plan, Task 10).
- All API access goes through a client generated from `internal/adminapi/openapi.yaml`, so an invented endpoint or field fails `typecheck`.
- Development runs against MSW mocks typed from the same contract, or proxies to a real rdadmin.

**Tech Stack:** Node 24 LTS, Vite, React 19, TypeScript (strict), Tailwind CSS v4, shadcn/ui (Radix), Motion, Recharts, dnd-kit, TanStack Router and Query, openapi-typescript, openapi-fetch, MSW, Vitest + Testing Library, Playwright, Lucide, `qrcode` (SVG output), `@fontsource-variable/inter`, `@fontsource-variable/jetbrains-mono`.

**Spec:** `docs/superpowers/specs/2026-10-06-phase-1b-web-ui-design.md`. **Depends on:** `docs/superpowers/plans/2026-10-06-phase-1b-backend.md`, merged first.

## Global Constraints

- **API:** only through `src/api/client.ts`, which wraps `openapi-fetch` typed by `src/api/schema.d.ts`. That file is generated by `npm run gen:api` and is never edited by hand. A raw `fetch` to `/admin/api` or `/setup` anywhere else is a defect. The single exception is the `EventSource` in `src/live/`.
- **Security** (`AGENTS.md` rule 6):
  - The CSRF token lives only in memory.
  - `credentials: 'same-origin'`.
  - Nothing about the session goes in `localStorage` or `sessionStorage`; only UI preferences may, and only until the server copy loads.
  - No third-party origins: fonts and icons are bundled.
  - No analytics, and no `eval`.
- **CSP** is `default-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`.
  - No library that injects `<style>` elements (this excludes sonner and CSS-in-JS).
  - No `data:` or `blob:` URLs for images. The TOTP QR is rendered as inline SVG elements.
  - Playwright fails a test on any CSP violation in the browser console.
- **Time and copy:** every time shows as relative ("2 min ago"), with the absolute local time on hover and focus. Copy is plain and specific: "Approve 3 devices", not "Submit".
- **Status colors** come from tokens only: `--status-online`, `--status-pending`, `--status-offline`, `--status-alert`, `--status-live`. Always paired with an icon or label.
- **Motion:** 150–250 ms; springs for layout; all of it off under `prefers-reduced-motion` (use Motion's `useReducedMotion`).
- **Accessibility:** WCAG 2.2 AA in both themes; everything works by keyboard; visible focus.
- **Viewports:** 1440×900 (primary), 1024×768, and 390×844.
- Every page has designed loading (skeleton), empty, and error-with-retry states.
- **Verification commands** (in `web/`): `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run e2e`. All must pass before a task is done.
- **No screenshots or browser use by agents** (token budget). Verification is text only: the commands above, whose output is pass/fail text. `npm run shots` exists for the user's visual reviews; agents never open its images. The user reviews visuals at the checkpoints (B1, B5) and whenever they choose.
- **This machine (Windows):** esbuild and Rollup's native binaries run natively, so `npm run dev` and the build work locally. npm 11 holds back install scripts until approved (`npm install-scripts approve <pkg>`); approve only what a task needs (for example Playwright's browser download) and say so in the report. If Windows App Control blocks a downloaded binary (as it blocks locally built Go test binaries), run that step in a container (`node:24`, or `mcr.microsoft.com/playwright` for e2e) and report it.
- **Go** on this machine: the backend's Go tests may be blocked by App Control; run them in a `golang:1.27` container (see `AGENTS.md`).

## Review Focus

1. **The session expires mid-use** (5 min idle without an open console tab, or an admin disabled the account). Any 401 sends the user to sign-in, keeps the page they were on as `?next=`, and doesn't loop or show raw errors. Test: `session-expiry.spec.ts` (A4).
2. **The live stream drops or the server restarts.** The UI keeps working: it falls back to 15 s refetches, reconnects on its own, refetches everything after a `resync`, and shows a quiet "Reconnecting…" indicator only after 10 s without a connection. Test: `live-reconnect.spec.ts` (A4).
3. **The fleet is large** (400 devices, 1,000 sessions). Lists paginate by cursor and the dashboard stays responsive. Test: `large-fleet.spec.ts` against the 400-device fixture (B5), plus checks that the devices list virtualises or paginates (B4).
4. **A slow or failing network call.** Each one shows a skeleton, then an inline error with retry. A mutation's button shows progress and can't be double-submitted. Test: MSW handlers with `delay` and 500 variants (A3), and specs per page.
5. **An admin who isn't the owner.** Owner-only pages and controls (users, server edit, thresholds) are hidden; direct navigation shows "Only owners can …" rather than a 403 dump. Test: `roles.spec.ts` (B7).

### A2: Generated API client and request wrapper

**Files:**
- Create: `web/src/api/schema.d.ts` (generated), `web/src/api/client.ts`, `web/src/api/errors.ts`, `web/src/api/csrf.ts`
- Test: `web/src/api/client.test.ts`

**Interfaces:**
- `api` is an `openapi-fetch` client typed by `paths`, base URL `''`. Middleware:
  - **Requests:** on POST, PUT, PATCH and DELETE, set `X-CSRF-Token` from `csrf.get()`.
  - **Responses:** a body with `csrf_token` (sign-in, TOTP, enroll-verify, password, me) → `csrf.set()`. 401 → `auth.onUnauthorized()`. Non-2xx → throw `ApiError`.
- `class ApiError extends Error { status: number; code: string; requestId?: string }`, parsed from `{"error":{"code","message","request_id"}}`.
- `csrf`: `get(): string`, `set(t: string)`, `clear()`. Memory only.
- `unwrap<T>(p: Promise<{data?: T; error?: unknown}>): Promise<T>` for use with TanStack Query.
- `setupClient(token: string)`: an `openapi-fetch` client with the same error handling that sends `X-Setup-Token: <token>` on every request. It is used only by the setup wizard, and the token is held in memory.

- [ ] **Step 1: Failing tests (Vitest + MSW node):**
  - a CSRF header goes on POST but not GET;
  - the token is captured from a `/auth/login` response;
  - a 403 `csrf` becomes an `ApiError` with code `csrf`;
  - 401 calls `onUnauthorized` once;
  - `request_id` is kept;
  - a call to an undocumented path fails `tsc`. Add `src/api/typeguard.test-d.ts` with `// @ts-expect-error` on `api.GET('/admin/api/v1/nope')`, so `typecheck` proves the guard works.
- [ ] **Step 2:** Implement, then run `npm run gen:api && npm run typecheck && npm test`. Expected: PASS.

  - It exposes `useLiveStatus(): 'live' | 'reconnecting'`; `reconnecting` only after 10 s down.

  - If a check fails twice, run `/boost` once.
  - If it still fails, stop and report (`GEMINI.md` rule 5).

- **Report:** files changed, the commands with their output, and anything unsure or unfinished.
- **Patterns** (all in `web/src/README.md`; follow them, don't invent your own):
  - Query keys only from `queryKeys` (`src/lib/queryKeys.ts`). A paginated list that loads more pages (`useInfiniteQuery`) uses `queryKeys.<list>.infinite(params)`; a plain list uses `.list(params)`. Never share one key between the two.
  - Changes: `useMutation` with `unwrap(api.POST(…))`, then invalidate through `queryKeys`. The CSRF header is automatic.
  - Errors: `describeError(err)` from `src/api/errors.ts`, then branch on its `code` for the calm messages the brief lists.
  - Device names: always `<DeviceLink deviceId={id}>`, which opens the device panel over the current page (`?device=`); never link a device to `/devices`.
- **Guardrails the build enforces:** ESLint forbids `fetch`, `XMLHttpRequest`, `EventSource`, browser storage and importing `src/mocks` or `msw` in app code. Never add an `eslint-disable` for these; if you think you need one, stop and report. rdadmin's Content Security Policy blocks inline `<script>`, inline `<style>`, `style="…"` in HTML strings and `data:` URLs; if a library you add is blocked by it (a console error in e2e), stop and report rather than working around it. A `<style>` added at runtime is allowed only with the page's nonce: Radix gets it automatically; wrap the app's Motion use in `<MotionConfig nonce={cspNonce()}>` (`src/lib/cspNonce.ts`), which Motion's `popLayout` needs.

You may always touch `web/src/**` files that the brief names or that are new for it. You must **not** touch `src/api/schema.d.ts`, `src/api/client.ts`, `src/api/csrf.ts`, `src/live/**`, `src/mocks/**` (except adding fixture *data* when a brief says so), `vite.config.ts`, `eslint.config.js`, `scripts/`, the CI, or anything outside `web/`.
